/**
 * Bug_01 Fix Summary
 * 
 * CHANGE: Added actions_remaining field to game events
 * 
 * Modified Events:
 * - ATTACK_RESOLVED: now includes {"actions_remaining": N}
 * - ACTOR_MOVED: now includes {"actions_remaining": N}
 * 
 * Purpose:
 * The GUI uses these fields to update the action counter UI from CoreEngine state,
 * eliminating anticipatory decrements and ensuring GUI and CoreEngine stay in sync.
 * 
 * Architecture Principle:
 * CoreEngine COMMANDS (manages game logic, sends state updates)
 * GUI VISUALIZES (displays what CoreEngine tells it)
 * 
 * Key Implementation:
 * - CoreEngine calculates: MAX_ACTIONS_PER_TURN - _actions_this_turn - 1
 *   This gives the correct remaining actions AFTER this action was processed
 * - GUI reads this value and updates its display, no local calculations
 * 
 * Related Issue:
 * Hero with 2/2 actions playing a 2-cost card would incorrectly get
 * "Azioni esaurite" (actions exhausted) rejection. With this fix,
 * the action succeeds and the display correctly shows 0/2.
 */
